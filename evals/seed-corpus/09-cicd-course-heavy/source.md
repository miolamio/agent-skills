# Как настроить CI/CD за 30 минут 🚀

В современном мире автоматизация — это не роскошь, а необходимость. В этом руководстве мы погрузимся в настройку полноценного CI/CD пайплайна с нуля. Готовы? Поехали! ✨

## Что нам понадобится

Стоит отметить, что для прохождения этого туториала нужны минимальные знания:
→ Базовое понимание Git и GitHub
→ Опыт работы с командной строкой
→ Установленный Node.js версии 18+
→ Аккаунт на GitHub (бесплатный подойдет)

## Шаг 1: Создаем репозиторий

Если у вас нет существующего проекта, создайте новый -- это займёт минуту:

```bash
mkdir my-awesome-project
cd my-awesome-project
git init
```

## Шаг 2: GitHub Actions

Важно понимать, что GitHub Actions использует YAML-файлы в директории `.github/workflows/`. Создадим первый workflow:

```yaml
name: CI Pipeline
on:
  push:
    branches: [main]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: npm ci
      - run: npm test
```

Стоит подчеркнуть, что это — минимальная конфигурация. В production обычно добавляют больше шагов.

## Шаг 3: Деплой

Самое интересное — автоматический деплой "из коробки":

```yaml
deploy:
  needs: test
  runs-on: ubuntu-latest
  steps:
    - run: npx vercel --token ${{ secrets.VERCEL_TOKEN }}
```

Важно понимать, что секреты нужно настроить в Settings → Secrets.

## Готово! 🎉

Поздравляем -- вы настроили полноценный CI/CD пайплайн. Это — только начало вашего путешествия в мир DevOps. Дальше можно добавить:
- Покрытие тестами с Codecov
- Security сканирование с Snyk
- Performance тесты с Lighthouse CI
- Канареечные релизы

В современном мире DevOps без автоматизации никуда. Удачи в автоматизации!
