# API Reference: Authentication

## Обзор

Аутентификация основана на JWT-токенах. Все запросы должны включать валидный токен в заголовке `Authorization`.

## Получение токена

Чтобы получить токен, отправьте POST-запрос на эндпоинт `/auth/login`:

```bash
curl -X POST https://api.example.com/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email": "user@example.com", "password": "secret"}'
```

Ответ содержит токен.

## Использование токена

Передавайте токен в каждом запросе в заголовке `Authorization`.

## Время жизни токена

- Access token: 1 час
- Refresh token: 30 дней
- Idle timeout: 15 минут
- Absolute timeout: 8 часов

При истечении срока действия токена вы получите ошибку 401. Используйте механизм автоматического обновления refresh-токенов.

## Безопасность

Токены — чувствительные данные. Не передавайте их через незащищённые каналы и не сохраняйте в открытом виде на клиентской стороне.

Рекомендации:

- Храните токены в HttpOnly cookies.
- Используйте HTTPS для всех запросов.
- Регулярно ротируйте refresh-токены.
- Логируйте подозрительную активность.

## Коды ошибок

В production-окружении корректно обрабатывайте каждый из этих кейсов на стороне клиента. Игнорирование кодов ошибок ведёт к деградации UX.

Рекомендуем логировать все 4xx/5xx-ответы и отправлять их в централизованный sink.
