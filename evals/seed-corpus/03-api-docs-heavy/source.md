# API Reference: Authentication 🔐

## Обзор

Аутентификация в нашем API основана на JWT-токенах. Это позволяет обеспечить безопасный и масштабируемый доступ к ресурсам. Важно понимать, что все запросы должны включать валидный токен в заголовке Authorization.

В современном мире безопасность API — это не роскошь, а необходимость "из коробки". Стоит отметить, что наша архитектура полностью соответствует best practices индустрии.

## Получение токена

Чтобы получить токен, отправьте POST-запрос на эндпоинт `/auth/login`:

```bash
curl -X POST https://api.example.com/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email": "user@example.com", "password": "secret"}'
```

Ответ будет содержать токен.

## Использование токена

Стоит отметить, что токен необходимо передавать в каждом запросе в заголовке Authorization.

## Время жизни токена

→ Access token: 1 час
→ Refresh token: 30 дней
→ Idle timeout: 15 минут
→ Absolute timeout: 8 часов

В случае истечения срока действия токена, вы получите ошибку 401. В современных приложениях рекомендуется использовать механизм автоматического обновления токенов "из коробки".

## Безопасность

Важно понимать, что токены — это чувствительные данные. Никогда не передавайте их через незащищенные каналы и не сохраняйте в открытом виде на клиентской стороне -- это базовое требование.

Best practices:
- Храните токены в HttpOnly cookies
- Используйте HTTPS для всех запросов
- Регулярно ротируйте refresh токены
- Логируйте подозрительную активность

## Коды ошибок

Стоит подчеркнуть, что в production-окружении необходимо корректно обрабатывать каждый из этих кейсов на стороне клиента. Важно понимать, что игнорирование кодов ошибок ведёт к деградации UX 🚨.

В современном мире наблюдаемость — это критически важный пункт. Стоит отметить, что мы рекомендуем логировать все 4xx/5xx ответы и отправлять их в централизованный sink.
