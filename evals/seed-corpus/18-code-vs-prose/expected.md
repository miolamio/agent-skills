# Код против прозы: одинаковые символы, разный контекст

В этой заметке намеренно используются одни и те же символы внутри кода и в обычной прозе. Линтер должен срабатывать только на прозе.

## Внутри кода — линтер молчит

```python
# Стрелки и двойные дефисы внутри кода допустимы:
result = a --> b   # стрелка как комментарий
flag = parser.parse("--verbose")  # двойной дефис в CLI
quote = "He said \"hello\""       # прямые кавычки
arrow_ops = {"→": "shift", "←": "back"}  # ASCII-описание
```

И inline-код тоже не должен ломаться: `→`, `--`, `"hello"` — всё это в `code`-спанах.

Ниже ещё блок:

```bash
# CLI-флаги используют двойной дефис -- это норма
curl https://api.example.com --header "Authorization: Bearer XXX"
echo "переход → следующий шаг"
```

## А вот в прозе те же символы запрещены

В прозе двойной дефис — маркер, который линтер должен поймать. Замена на тире решает проблему.

Стрелка в обычном тексте также недопустима. Особенно в начале строки. Используйте слова «после этого» или «состоит из».

И прямые кавычки в прозе: «пример» — должны быть заменены на «ёлочки».

Чистота прозы — не каприз, а требование стиля.
